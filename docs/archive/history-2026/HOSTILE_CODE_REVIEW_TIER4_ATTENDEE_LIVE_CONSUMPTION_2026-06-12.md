# Hostile Code Review — Tier 4 Attendee Live Consumption

Date: 2026-06-12
Repo: agency-event-os
Scope: Tier 4 attendee live-consumption gauntlet, live access control, LiveKit ingress/attendee room alignment, generated evidence, and runtime revocation behavior.

## Review Result

PASS AFTER FIXES — artifact required correction before updater handoff.

## Issues Found

1. The attendee gauntlet claimed evidence was generated by the run while reading a pre-existing RTMP evidence file.
2. The attendee gauntlet did not enforce that the attendee event id matched the controlled RTMP evidence event id.
3. Attendee LiveKit tokens could target a different room than the StreamYard-compatible RTMP ingress room.
4. The attendee proof used HTTP/API checks only and did not force an attendee browser to reach the live stage surface.
5. Permit/revoke server actions lacked explicit live-control authorization and did not write backend stage-stream access logs.
6. Revocation denied future tokens but did not attempt to remove the already-connected LiveKit attendee participant.
7. The backend log filter could miss real permit/revoke/re-permit records because it relied on loose message text patterns.
8. The prior artifact accidentally omitted `services/reports`, causing typecheck failure in a fresh reopened ZIP.

## Fixes Applied

1. Added `tier4RunId` to controlled RTMP evidence and passed `TIER4_CONTROLLED_MEDIA_EVIDENCE_RUN_ID` into the attendee gauntlet.
2. Made attendee proof fail if controlled media evidence event id and attendee event id diverge.
3. Added shared LiveKit room naming utility and aligned attendee main-stage token room with the StreamYard-compatible ingress room.
4. Added browser-stage proof using Playwright from inside the attendee gauntlet.
5. Added test IDs for the stage player and attendee LiveKit surface so browser proof can assert the correct surface.
6. Added live-control authorization and logging to attendee live-control server actions.
7. Added best-effort LiveKit participant removal during revoke.
8. Fixed backend log filtering to use `attendee_access_decision` signal and attendee id.
9. Restored missing `services/reports` source files.
10. Expanded `validate:tier4-attendee-live-consumption-contract` to catch these failure classes.

## Remaining Unproven Layers

- Deployed Tier 4 provider proof has not been run from this sandbox.
- GitHub Actions are not verified from this sandbox.
- True audio waveform analysis in the attendee browser is not implemented. Current proof requires same LiveKit room, observed controlled broadcaster participant/media connection, browser reaches LiveKit stage surface, and attendee token resolves for that same room.

## Completion Impact

The previous artifact should not be treated as final. Use the corrected baseline ZIP generated after this hostile pass.
